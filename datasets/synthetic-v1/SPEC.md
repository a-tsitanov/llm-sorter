# synthetic-v1 — синтетические транскрипты разговоров

Назначение: тесты и оценка качества llm-sorter (decide, guard, discover) на данных с известной эталонной разметкой.

## Формат файла

Один разговор = один JSON-файл в `transcripts/`, формат, который читает `LocalDirSource`:

```json
{
  "id": "fin-crypto-trading-001",
  "text": "Оператор: ...\nКлиент: ...\n...",
  "metadata": {
    "gold_path": "finance/crypto/trading",
    "lang": "ru",
    "kind": "normal",
    "note": "необязательно: что проверяет файл"
  }
}
```

- `id` — `^[a-z0-9-]+$`, уникальный, совпадает с именем файла без `.json`.
- `text` — транскрипт в стиле ASR: реплики с метками говорящих (`Оператор:`/`Клиент:`, `Agent:`/`Customer:`, `A:`/`B:` и т.п.), разговорные обороты, повторы, оговорки, иногда «э-э», без markdown. Длина 150–1500 слов; ~10% файлов длинные (2000–4000 слов).
- `metadata.gold_path` — эталонный путь в дереве ниже. Для шума — `other`.
- `metadata.kind`:
  - `normal` — явно про свою тему;
  - `near_miss` — лексика соседней темы, но по сути другая (проверка guard и decide), `gold_path` — истинная тема;
  - `noise` — ни к одной теме (`gold_path: other`);
  - `edge` — пустой/почти пустой/служебный текст (`gold_path: other`).
- `metadata.lang` — `ru`, `en`, `de`, `es`, `uk`, `kk`.

## Эталонное дерево (глубина 3)

| gold_path | Что внутри |
|---|---|
| finance/crypto/trading | торговля криптой: сигналы, плечи, фьючерсы, стопы, биржи |
| finance/crypto/wallets | кошельки, seed-фразы, потерянный доступ, переводы между кошельками |
| finance/banking/loans | кредиты, ипотека, рефинансирование, просрочки |
| finance/banking/cards | банковские карты: блокировка, лимиты, кэшбэк, спорные списания |
| health/dental | стоматология: запись, лечение, импланты, цены |
| health/insurance | медстраховка: ДМС, покрытие, отказы в выплате |
| travel/flights | авиабилеты: перенос, возврат, багаж, задержки |
| travel/hotels | отели: бронь, отмена, жалобы на номер |
| tech/internet | домашний интернет: обрывы, скорость, роутер, тарифы |
| tech/mobile | мобильная связь: роуминг, SIM, списания, перенос номера |

## Состав

| Группа | Кол-во | Языки |
|---|---|---|
| normal, на каждый из 10 листьев | 12 (=120) | ~60% ru, ~25% en, остальное de/es/uk/kk |
| near_miss | 15 | смешанно |
| noise (погода, футбол, рецепты, ремонт машины, семейное) | 15 | смешанно |
| edge | 6 | — |

Итого ~156 файлов. 12 на лист > `min_cluster_size: 10`, поэтому discover может найти каждую тему с нуля.

Примеры edge: пустая строка, только пробелы, «Алло? Алло, вас не слышно…» и обрыв, автоответчик, гудки/`[неразборчиво]`, очень короткое «Да. Нет. Пока.»

## Префиксы id

`fin-crypto-trading-`, `fin-crypto-wallets-`, `fin-bank-loans-`, `fin-bank-cards-`, `health-dental-`, `health-insurance-`, `travel-flights-`, `travel-hotels-`, `tech-internet-`, `tech-mobile-`, `nearmiss-`, `noise-`, `edge-`; номер — 3 цифры.

## Правила генерации

- Разные сценарии внутри темы: не 12 вариаций одной жалобы.
- Разные роли: колл-центр, звонок другу, консультация, голосовое.
- Имена, суммы, даты — вымышленные; никаких реальных персональных данных.
- В `normal` тема очевидна человеку; в `near_miss` в `note` написано, какую соседнюю тему он имитирует.
