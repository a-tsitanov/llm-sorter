# Параметры окружения

Приложение читает переменные окружения и файл `.env` в **текущем рабочем каталоге**, поэтому запускайте команды из корня проекта. Переменная окружения имеет приоритет над значением из `.env`, затем используются значения `AppConfig` по умолчанию. Относительные пути также разрешаются относительно текущего рабочего каталога. Ниже указаны значения по умолчанию из кода, а не обязательно значения из вашего `.env`. После изменения `.env` перезапустите соответствующие процессы.

Шаблон — [`.env.example`](../.env.example). Ключи и Telegram-сессию храните в `.env` или в окружении и не включайте в репозиторий. Описание настройки конкретного локального LiteLLM — [в отдельной инструкции](../deploy/litellm-local/README.md).

## Модели

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `LLM_URL` | `http://localhost:1234/v1` | Базовый URL сервера для выбора темы и эмбеддингов; также используется для остальных ролей, если их отдельные URL пусты. Для локального LiteLLM текущей машины задан `http://127.0.0.1:4001/v1`. |
| `LLM_API_KEY` | `lm-studio` | Ключ основного сервера. Значение по умолчанию — пример для локального сервера; используйте ключ вашего шлюза. |
| `LLM_GUARD_URL` | пусто | Отдельный базовый URL модели проверки конечной темы; пустое значение использует `LLM_URL`. |
| `LLM_GUARD_API_KEY` | пусто | Ключ отдельного сервера проверки. Если указан `LLM_GUARD_URL`, пустой ключ заменяется на `LLM_API_KEY`; без отдельного URL используется основной клиент и основной ключ. |
| `LLM_TEXT_URL` | пусто | Отдельный базовый URL текстовой модели, предлагающей темы; пустое значение использует `LLM_URL`. |
| `LLM_TEXT_API_KEY` | пусто | Ключ отдельного текстового сервера. Если указан `LLM_TEXT_URL`, пустой ключ заменяется на `LLM_API_KEY`; без отдельного URL используется основной клиент и основной ключ. |
| `MODEL_DECIDE` | `lfm2` | Имя или алиас модели выбора дочерней темы. При использовании локальной D1 укажите `d1-3b`. |
| `DECIDE_PROTOCOL` | `chat` | `chat` вызывает chat completions со строгой JSON-схемой; `systemone` вызывает `/v1/systemone` с decision-моделью, например D1. Убедитесь, что выбранный сервер поддерживает нужный маршрут. |
| `MODEL_GUARD` | `qwen3-4b` | Имя модели, проверяющей соответствие текста выбранному листу. |
| `MODEL_TEXT` | `qwen3-4b` | Имя текстовой модели для discover и сравнения предлагаемых тем. |
| `MODEL_EMBED` | `bge-m3` | Имя embedding-модели, используемой для кластеризации и сравнения тем. Запросы идут на основной `LLM_URL`. |
| `GUARD_ENABLED` | `true` | При `false` проверка листа не вызывается; результат содержит `gate: skipped`. |
| `MULTI_TOPIC` | `true` | Повторять выбор по оставшимся темам на каждом уровне и публиковать каждый подходящий лист; `false` оставляет одну тему. |
| `MULTI_MAX_CHOICES` | `3` | Максимум выбранных веток на узел. Если оставшиеся ветки не проверены, снимок истории получает `truncated: true`. |
| `EMBED_MAX_CHARS` | `1200` | Максимум символов каждого текста для эмбеддинга. Остальная часть текста в эмбеддинге не учитывается; это не точный лимит токенов. |
| `EMBED_BATCH_SIZE` | `8` | Максимум текстов в одном запросе эмбеддингов. При ошибке размера запроса уменьшите значение и/или `EMBED_MAX_CHARS`. |

Имена должны существовать на соответствующих серверах; это алиасы API, которые не обязаны совпадать с именами файлов моделей. Модель выбора, guard и text должны поддерживать используемые приложением форматы ответов. Качество классификации и возможность отправлять большие запросы зависят от модели и доступного контекста.

## Хранение и RabbitMQ

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `SQLITE_PATH` | `./data/sorter.db` | Путь к SQLite с деревом, журналом изменений и состоянием learner. Файл блокировки единственного learner создаётся рядом. |
| `RABBIT_URL` | `amqp://guest:guest@localhost:5672/` | AMQP-адрес RabbitMQ для процессов приложения; при изменении хостового порта Compose обновите его. |
| `INBOX_QUEUE` | `llm-sorter.inbox` | Очередь входящих сообщений. DLQ автоматически называется `<INBOX_QUEUE>.dlq`. |
| `CLASSIFIED_EXCHANGE` | `llm-sorter.classified` | Topic exchange результатов; routing key — путь темы через точку. |
| `CLASSIFIED_ARCHIVE` | `llm-sorter.classified.all` | Очередь-архив результатов, привязанная к exchange по `#`. |
| `CLASSIFIED_HISTORY` | `llm-sorter.classified.history` | Отдельный RabbitMQ Stream полных результатов классификации, включая сообщения без темы. |
| `HISTORY_MAX_AGE` | `30D` | Максимальный возраст записей истории с момента публикации; значение должно совпадать у всех процессов. |
| `HISTORY_MAX_BYTES` | `10737418240` | Лимит размера истории в байтах; при его достижении записи могут удаляться раньше 30 дней. |
| `OTHER_STREAM` | `llm-sorter.other` | RabbitMQ stream материалов для learner и сообщений без подходящей темы. |
| `OTHER_MAX_AGE` | `30D` | Максимальный возраст записей stream; формат — целое число с единицей `Y`, `M`, `D`, `h`, `m` или `s`, например `30D` или `12h`. Learner переиздаёт ожидающие записи старше половины этого возраста. |
| `OTHER_MAX_BYTES` | `10737418240` | Максимальный размер stream в байтах: по умолчанию 10 GiB. Удаление старых записей из-за размера может привести к потере ожидающих данных. |

Все процессы, объявляющие один stream, должны использовать одинаковые `OTHER_MAX_AGE` и `OTHER_MAX_BYTES`. Параметры уже созданного stream нельзя сменить простым перезапуском: несовпадение вызывает `PRECONDITION_FAILED`. В RabbitMQ находятся входящие сообщения, архив и stream; не удаляйте том или очереди, не учитывая последствия.

## Обработка и метрики

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `PROCESS_CONCURRENCY` | `16` | Число сообщений, одновременно обрабатываемых одним процессом. Можно переопределить `llm-sorter process --concurrency N`; подбирайте с учётом возможностей моделей. |
| `TREE_REFRESH_S` | `1.0` | Интервал в секундах, через который обработчик проверяет ревизию дерева в SQLite. |
| `LEARNER_CHECK_S` | `30.0` | Интервал в секундах между проверками порогов discover и сохранением позиции learner при штатной работе. |
| `LEARNER_MAX_BATCH` | `2000` | Максимум сообщений узла за проход discover; сначала берутся новые, затем уже рассмотренные. Если порог discover или минимальный размер кластера больше, применяется больший лимит. При разделении листа переобрабатывается весь его буфер. |
| `OTHER_REFRESH_S` | `86400.0` | Интервал в секундах между переизданиями старых ожидающих записей stream, чтобы продлить их хранение. Время последнего переиздания сохраняется в SQLite. |
| `METRICS_PORT` | `9100` | HTTP-порт Prometheus-метрик обработчика; `0` отключает метрики. Можно переопределить `process --metrics-port`. |
| `LEARNER_METRICS_PORT` | `9102` | HTTP-порт метрик learner; `0` отключает метрики. Можно переопределить `learn --metrics-port`. |

## Источники

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `SOURCE_DIR` | `./data/inbox` | Каталог для `feed dir`. Фидер читает файлы верхнего уровня `.txt` и `.json` и хранит подтверждённые ID в `.seen.json` внутри каталога. |
| `POLL_INTERVAL_S` | `10.0` | Пауза между циклами опроса источника в секундах. Общая настройка для всех встроенных фидеров; для Telegram в шаблоне рекомендуется `60`. |
| `TG_API_ID` | `0` | Числовой API ID приложения Telegram; требуется для `feed tg` и `tg-folders`. |
| `TG_API_HASH` | пусто | Секретный API hash приложения Telegram. |
| `TG_SESSION` | пусто | Авторизованная Telethon StringSession. Встроенная CLI-команда её не создаёт. |
| `TG_FOLDERS` | пусто | Имена папок Telegram через запятую; проверить доступные имена можно через `uv run llm-sorter tg-folders`. |
| `TG_STATE_FILE` | `./data/tg_state.json` | Файл сохранённых курсоров сообщений по чатам. |
| `TG_BACKFILL` | `20` | Количество последних сообщений, просматриваемых для чата при первом опросе без курсора. |
| `TG_MIN_LEN` | `80` | Минимальная длина текста после удаления пробелов по краям; более короткие сообщения не передаются на классификацию. |

## Docker Compose и локальный LiteLLM

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `RABBIT_PORT` | `5672` | Хостовый порт AMQP в `docker-compose.yml`; переменная Compose, не поле `AppConfig`. Если изменить, также измените `RABBIT_URL`. |
| `RABBIT_MGMT_PORT` | `15672` | Хостовый порт RabbitMQ Management в Compose; переменная Compose, не поле `AppConfig`. |
| `LITELLM_MASTER_KEY` | не задан | Ключ отдельного LiteLLM, когда он запускается с такой переменной. Это настройка LiteLLM, а не `AppConfig`; `LLM_API_KEY` клиента должен совпадать с допустимым ключом шлюза. |

`RABBIT_PORT` и `RABBIT_MGMT_PORT` используются при `docker compose up`; приложение к ним напрямую не обращается. На уже настроенной macOS-машине ключ LiteLLM задан в пользовательском LaunchAgent; при ручном запуске его нужно передать отдельно, как описано в инструкции локального шлюза.

## Параметры дерева — не переменные окружения

Порог обнаружения тем, глубина и ограничения дерева задаются в настройках самого дерева, а не через перечисленные переменные. Значения по умолчанию определены в `src/llm_sorter/domain/tree.py`; экспортировать текущие настройки вместе с темами можно командой `uv run llm-sorter topics export -o topics.yml`. До изменения настроек через импорт изучите текущий YAML и семантику `--replace`: эта опция архивирует существующие темы.
