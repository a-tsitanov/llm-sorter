# Несколько тем и большие буферы

## Классификация по нескольким темам

SystemOne возвращает один выбор, поэтому обработчик последовательно исключает уже выбранные варианты. Каждый лист публикуется в exchange отдельно; единый снимок всех назначений записывается в history stream. Повторный выбор не даёт достоверной вероятности.

| Механизм | Состояние | Детали |
|---|---|---|
| Выбор нескольких веток | Реализован | `MULTI_TOPIC`, `MULTI_MAX_CHOICES`; `other` останавливает поиск на узле. При исчерпании лимита снимок отмечается `truncated`. |
| Проверка соответствия | Частично | Guard проверяет конечные листья, если включён; промежуточные ветки не проверяются отдельно. Точность нужно оценить на размеченных данных. |
| Публикация и история | Реализовано | Одно событие на лист и один снимок с полным списком в `CLASSIFIED_HISTORY`; при ошибке модели снимок помечается неполным. |
| Состояние learner | Реализовано | Новые записи учитываются по паре узел/ID; старые записи без признака ветки сохраняют прежнюю семантику. |
| Переобработка и отзыв старых тем | Частично | `history replay` отправляет снимки в inbox; отдельные события отзыва темы не публикуются, потребитель должен сверять полный снимок и его версию. |
| Качество и нагрузка | Не проверено | Нужны precision/recall на размеченных примерах, оценка числа вызовов и замеры на реальных данных. Отдельного общего бюджета на всё дерево пока нет. |

RabbitMQ topic exchange уже поддерживает публикацию в несколько routing key; замена брокера сама по себе не решает выбор кандидатов, идемпотентность и согласование результатов.

## Масштабирование discover

Learner рассматривает ограниченное число сообщений за проход (`LEARNER_MAX_BATCH`): сначала новые, затем ранее рассмотренные. Остальные остаются в буфере; после разделения листа переобрабатывается весь буфер. Остаток новых сообщений меньше порога ждёт следующих сообщений. Размер окна может скрыть редкие темы или разбить связанные сообщения по проходам. Для оценки нужны замеры времени, памяти, качества и числа запросов на репрезентативных 10–20 тысячах сообщений; возможные следующие шаги — репрезентативная выборка и инкрементальные центроиды.

Ограничение `EMBED_MAX_CHARS` отсекает хвост текста, а число символов не равно числу токенов. Для длинных документов следующий шаг — токенизатор конкретной модели, разбиение с перекрытием и агрегация эмбеддингов с оценкой качества. Лимит контекста группировки зависит также от родительских и соседних тем, поэтому пакет из 12 кластеров не гарантирует совместимость с любым контекстом модели.
